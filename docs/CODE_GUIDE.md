# Руководство по коду

Как устроен Shopping List и где что менять. Установка и запуск описаны в [README.md](../README.md), база данных — в [DATABASE.md](DATABASE.md).

## Общая схема

```
Браузер (static/app.js)
   │  fetch, JSON
   ▼
app.py  — маршруты, проверка ввода, подсчёт итогов
   │  вызовы функций
   ▼
db.py   — SQL-запросы, объединение товаров
   │
   ▼
shopping.db (SQLite, таблицы из schema.sql)
```

Страница одна (`templates/index.html`). Всё остальное общение идёт через REST API в формате JSON. Сервер не рендерит списки в HTML — это делает `app.js`.

## Файлы

| Файл | Отвечает за |
|------|-------------|
| `app.py` | создание приложения (`create_app`), маршруты, проверка ввода, ответы об ошибках, итоги |
| `db.py` | подключение к SQLite, создание таблиц, все SQL-запросы, правило объединения товаров |
| `schema.sql` | `CREATE TABLE` для `lists` и `items` |
| `templates/index.html` | разметка страницы: панель списков, форма товара, таблица, итоги |
| `static/app.js` | запросы к API, отрисовка, показ ошибок, открытие списка по ссылке `#list-N` |
| `static/style.css` | стили, в том числе для экранов уже 720px |
| `mcp_server/server.py` | MCP-сервер для Claude Code: чтение базы, итоги, проверка целостности (см. [README](../README.md#mcp-сервер-и-skill-для-claude-code)) |

## app.py

### Создание приложения

`create_app(database=None)` собирает приложение:

- путь к базе берётся из аргумента, иначе `shopping.db` рядом с кодом. Это позволяет тестам работать на временной базе: `create_app("test.db")`;
- `db.init_db()` создаёт таблицы, если их нет (`CREATE TABLE IF NOT EXISTS`);
- `app.json.ensure_ascii = False` — русский текст в JSON без `\uXXXX`;
- `app.json.sort_keys = False` — ошибки в ответе идут в порядке полей формы.

В конце файла `app = create_app()` — именно этот объект находит `flask --app app run`.

### Проверка ввода

Функции `clean_name`, `clean_qty`, `clean_price` принимают значение и словарь `errors`. Если значение плохое, функция кладёт сообщение в `errors[поле]` и возвращает `None`. Так за один запрос собираются все ошибки сразу, а не только первая.

Правила:

| Поле | Правило | Сообщение |
|------|---------|-----------|
| `name` | непустая строка после обрезки пробелов, до 100 символов; повторные пробелы схлопываются | «… не может быть пустым» |
| `qty` | целое число > 0 и ≤ 1 000 000; принимаются `3`, строка `"3"` и число `3.0`; не принимаются `"1.5"`, `"3.0"` и `true` | «… должно быть больше нуля» / «… целым числом» |
| `price` | необязательно; число ≥ 0 и ≤ 100 000 000; запятая или точка; округляется до копеек | «Цена не может быть отрицательной» / «… должна быть числом» |

Если `errors` не пуст, маршрут бросает `ValidationError(errors)`. Обработчик `on_validation_error` превращает его в ответ `400`:

```json
{"error": "Название товара не может быть пустым; Количество должно быть больше нуля",
 "errors": {"name": "...", "qty": "..."}}
```

Сервер — единственное место, где проверяется ввод. На странице нет своей проверки, чтобы правила не расходились.

### Ответы

- Запросы, меняющие товары (`POST` товара, `PATCH` и `DELETE` товара), возвращают **весь список** — `list_view()`: `{list, items, totals}`. Страница сразу перерисовывается без второго запроса.
- `POST` товара дополнительно возвращает `item` и `merged` (был ли товар объединён). Код ответа: `201` — новый товар, `200` — объединён.
- Не найден список или товар — `404` с `{"error": "..."}`.
- Удаление списка — `204` без тела.

### Итоги

Считаются в `list_view()` по уже загруженным товарам: число позиций и сумма `price_cents` (пустая цена = 0) для трёх групп — все, купленные, некупленные.

## db.py

- `get_db()` открывает одно соединение на запрос (хранится во `flask.g`), `close_db()` закрывает его после запроса.
- `connect()` включает `PRAGMA foreign_keys = ON` — без этого SQLite не удаляет товары вместе со списком.
- Изменения выполняются внутри `with conn:` — это транзакция: либо всё, либо ничего.
- Все значения передаются через `?`, строки в SQL не склеиваются.

### Объединение товаров — `add_item()`

1. `name_key(name)` — ключ сравнения: пробелы схлопнуты, `casefold()`. Считается в Python, потому что `lower()` в SQLite не понимает кириллицу.
2. Ищется товар с тем же `name_key` в том же списке.
3. Нашёлся — `qty` складывается, цены складываются (пустая = 0; если пусто у обоих — остаётся пусто), `bought` сбрасывается в 0. Название остаётся как у первого товара.
4. Не нашёлся — вставляется новая строка.

Возвращает `(item, merged)`.

## static/app.js

- `api(method, url, data)` — обёртка над `fetch`. При ошибке бросает `ApiError` с `message` и `errors` по полям; при недоступном сервере — понятный текст.
- `state` — список списков и `currentId` открытого списка.
- `renderLists()`, `renderListView(view)`, `renderTotals(totals)` — полная перерисовка из ответа сервера. Своего состояния товаров на странице нет.
- `showItemErrors(err)` выводит ошибки списком и подсвечивает поля (`fieldInputs` связывает имя поля из API с id инпута).
- Весь текст вставляется через `textContent`, не через `innerHTML` — пользовательский ввод не может стать HTML.
- Открытый список запоминается в адресе (`#list-3`): переживает обновление страницы, работает переход по ссылке (`hashchange`).

## Как добавить изменение

**Новое поле товара** (например, «отдел»):

1. `schema.sql` — колонка. Для существующей базы нужен `ALTER TABLE` (см. [DATABASE.md](DATABASE.md#изменение-схемы)).
2. `db.py` — `_item_dict`, `add_item` (и правило при объединении).
3. `app.py` — функция `clean_…` и чтение поля в `api_add_item`.
4. `index.html` — инпут в форме; `app.js` — отправка поля, колонка в `renderListView`, запись в `fieldInputs`.

**Новый маршрут API:** функция в `db.py` для SQL, маршрут в `create_app` в `app.py`, ошибки ввода — через `ValidationError`, «не найдено» — через `not_found()`.

## Проверка после изменений

Быстрая проверка API на временной базе, без запуска сервера:

```python
from app import create_app
c = create_app("test.db").test_client()
lid = c.post("/api/lists", json={"name": "Тест"}).json["id"]
c.post(f"/api/lists/{lid}/items", json={"name": "Молоко", "qty": 1, "price": "80"})
r = c.post(f"/api/lists/{lid}/items", json={"name": "молоко", "qty": 2})
assert r.json["merged"] and r.json["item"]["qty"] == 3
```

Ручная проверка в браузере — по пунктам [TZ.md](../TZ.md): списки, ошибки ввода, объединение, отметка, удаление, итоги, данные после перезапуска сервера.

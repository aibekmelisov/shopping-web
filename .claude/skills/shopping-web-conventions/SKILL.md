# Shopping List (веб): правила проекта

Веб-приложение списков покупок по [TZ.md](../../../TZ.md). Python 3.10+ (проверено на 3.14), Flask 3, SQLite, одна страница на HTML/CSS/JS без фреймворков и сборки.
Валюта — рубль, деньги хранятся целым числом в копейках. Один пользователь, без авторизации. Интерфейс и сообщения — на русском.

Подробности: [docs/CODE_GUIDE.md](../../../docs/CODE_GUIDE.md) (код), [docs/DATABASE.md](../../../docs/DATABASE.md) (база), [README.md](../../../README.md) (запуск, API).

## Где лежит логика

Зависимости только сверху вниз: `static/app.js → app.py → db.py → shopping.db`.

| Файл | Что здесь | Чего здесь быть не должно |
|---|---|---|
| `app.py` | маршруты в `create_app`, проверка ввода (`clean_*`), ответы и коды, итоги (`list_view`) | SQL-запросов |
| `db.py` | соединение, транзакции, все SQL-запросы, `name_key`, правило объединения (`add_item`) | Flask-ответов, текстов ошибок ввода |
| `schema.sql` | `CREATE TABLE IF NOT EXISTS` для `lists`, `items` | данных |
| `static/app.js` | вызовы API через `api()`, отрисовка из ответа сервера, показ ошибок | своих правил проверки и расчёта итогов |
| `mcp_server/server.py` | MCP-сервер только для чтения | любых изменений данных |

- **Ввод проверяется только на сервере.** Новая проверка — функция `clean_<поле>(value, errors)` в `app.py`: кладёт сообщение в `errors[поле]` и возвращает `None`. Все ошибки запроса собираются вместе, затем `raise ValidationError(errors)` → `400 {"error", "errors"}`. На странице поле подсвечивается через `fieldInputs` в `app.js`.
- **«Не найдено»** — `return not_found("… не найден")` → `404`.
- Запросы, меняющие товары, возвращают **весь список** (`list_view`), страница перерисовывается из ответа целиком.
- Изменения в базе — только внутри `with conn:` (транзакция), значения — только через `?`.
- Каждое соединение — с `PRAGMA foreign_keys = ON` (иначе не работает каскадное удаление).

## Правила данных (не нарушать)

- **Деньги** — `int` в копейках, колонка и поле с суффиксом `_cents` (`price_cents`). `NULL` = «не указано». Не использовать `float`/`REAL` для денег. Рубли — только при выводе (`formatMoney` в JS).
- **Цена — за всю позицию**, не за штуку: поэтому при объединении цены складываются.
- **Сравнение названий** — только через `db.name_key()` (пробелы схлопнуты, `casefold()`), результат хранится в колонке `name_key`. Не использовать `lower()`/`LIKE`/`COLLATE NOCASE` в SQL для названий: SQLite не знает регистр кириллицы.
- **Объединение** (`add_item`): тот же `name_key` в том же списке → `qty` складывается, цены складываются (`NULL` = 0, но `NULL + NULL = NULL`), `bought = 0`, название остаётся первое. Гарантируется `UNIQUE (list_id, name_key)`.
- **Количество** — целое `> 0`; **цена** — `≥ 0`; названия — непустые, до 100 символов.
- **Итоги** не хранятся, считаются при каждом запросе: число позиций и сумма для «всего / куплено / осталось».

## Изменение схемы (чек-лист)

`CREATE TABLE IF NOT EXISTS` не меняет существующие таблицы — у пользователя уже есть `shopping.db` с данными.

1. Изменить `schema.sql` (для новых баз).
2. Для существующих баз добавить миграцию в `db.init_db()`: проверить `PRAGMA table_info(...)` и выполнить `ALTER TABLE … ADD COLUMN …`, если колонки нет. Сложные изменения — через новую таблицу и `INSERT INTO … SELECT` (см. DATABASE.md).
3. Обновить `db.py` (`_item_dict`, запросы), `app.py` (`clean_*`, маршрут), `index.html` и `app.js`.
4. Если меняются инварианты — обновить `check_integrity` в `mcp_server/server.py`.
5. Обновить `docs/DATABASE.md` (таблица колонок, правила) и при необходимости README (API).

Не удалять и не пересоздавать `shopping.db` без явной просьбы пользователя — в ней его данные.

## Как называть

| Что | Шаблон | Пример |
|---|---|---|
| Таблица, колонка | `snake_case`, таблица во множественном числе | `items`, `price_cents`, `name_key` |
| Функция в `db.py` | глагол + сущность | `get_list`, `add_item`, `set_bought`, `delete_item` |
| Маршрут в `app.py` | `api_<действие>_<сущность>` | `api_add_item`, `api_rename_list` |
| Проверка ввода | `clean_<поле>` | `clean_qty`, `clean_price` |
| URL API | `/api/<сущности во мн. числе>/<id>` | `/api/lists/3/items`, `/api/items/7` |
| id в HTML | `kebab-case` | `add-item-form`, `item-errors` |
| JS-функция | `camelCase`, отрисовка — `render*` | `renderListView`, `showItemErrors` |

## Интерфейс

- Весь пользовательский текст вставлять через `textContent` / `el(...)`, **никогда через `innerHTML`**.
- Тексты ошибок пишет сервер; страница их только показывает.
- Цвета — CSS-переменные из `:root` в `style.css`. Ширина до 720px — одна колонка.
- Открытый список хранится в адресе `#list-<id>`.

## Проверка изменений

1. Быстрая проверка API без сервера — тестовый клиент на временной базе (пример в CODE_GUIDE.md):
   ```python
   from app import create_app
   c = create_app("<временный путь>/test.db").test_client()
   ```
   Запускать `.venv\Scripts\python.exe -X utf8 …` (иначе кириллица в выводе ломает консоль Windows). Временную базу класть вне проекта и не трогать `shopping.db`.
2. Ручная проверка в браузере по пунктам TZ.md: `.venv\Scripts\python.exe -m flask --app app run`, затем http://127.0.0.1:5000.
3. После изменений, затрагивающих данные, вызвать MCP-инструмент `check_integrity`.

## MCP-сервер `shopping-db`

Подключён в `.mcp.json`, код в `mcp_server/server.py`. Открывает `shopping.db` **только на чтение** (путь можно сменить переменной `SHOPPING_DB`).

| Инструмент | Когда использовать |
|---|---|
| `list_lists` | обзор: все списки с итогами |
| `get_list(list_id)` | товары и итоги одного списка — как на странице |
| `find_items(query)` | поиск товара по части названия во всех списках (кириллица без учёта регистра) |
| `describe_schema` | актуальная схема и число строк — перед изменением схемы |
| `run_select(sql, limit)` | произвольный `SELECT`/`WITH … SELECT`, один запрос, до 500 строк |
| `check_integrity` | нарушения правил: дубли, неверный `name_key`, `qty ≤ 0`, отрицательные цены, висячие товары |

- Для вопросов о данных пользователя сначала использовать эти инструменты, а не писать скрипты.
- Цены в ответах — в копейках (`price_cents`) и строкой в рублях (`price_rub`, `rub`).
- **Изменять данные через MCP нельзя и не нужно обходить это** (например, правкой файла базы напрямую). Все изменения — через API приложения, где работают проверка ввода и объединение. Если пользователь просит исправить данные — предложить способ через API и спросить подтверждение.
- Если инструменты `shopping-db` недоступны: проверить, что сервер одобрен в Claude Code, и что пути в `.mcp.json` совпадают с расположением проекта и `.venv`.
